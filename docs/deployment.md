# Deploy with Supabase, Render and Vercel

1. Complete the local setup and migration in the README. Verify Supabase login, both live repository imports, real Gemini responses, cross-user denial and quota exhaustion on a dedicated test project. Check that a failed refresh preserves the previous snapshot and that an interrupted job resumes on a native PostgreSQL connection.
2. Choose and confirm a GitHub owner and private repository name. From the project root inspect `git status --ignored`, verify that local environment files are ignored, and review staged changes for credentials. Authenticate to GitHub using your own account and push the reviewed commits to the confirmed destination.
3. Obtain approval before creating public endpoints. In Render select New → Blueprint and choose the private GitHub repository. The root `render.yaml` declares one free Python API, a pinned dependency build, the uvicorn startup command and a health check. Enter backend secrets in Render's environment panel. Set `FRONTEND_URL` to the exact approved Vercel origin. Add the optional public-read GitHub token there if needed. [Render blueprint reference](https://render.com/docs/blueprint-spec)
4. In Vercel import the same repository, choose **frontend** as the root, **Vite** as the preset and **dist** as output. Configure the three public variables from `frontend/.env.example`. Use the Render HTTPS origin for `VITE_API_URL`. The checked-in SPA rewrites support direct workspace links. Redeploy the frontend after changing Vite variables. [Vercel Vite guide](https://vercel.com/docs/frameworks/frontend/vite)
5. Add the approved Vercel origin to Supabase Authentication URL Configuration and set the production Site URL. Configure delivery of confirmation emails for external users. Use the Render and Vercel production origins consistently.
6. Visit the production API health endpoint and require a configured status. Visit the actual frontend in a fresh browser, register, confirm email and import a small repository. Open a source citation, inspect dependency edges, refresh the page and verify persisted history. Use a second account to check access denial. Record the live URLs and observed results in PROGRESS.md only after these checks.

Render's free instance can sleep. An interrupted import starts again from the beginning after wake-up. Keep an eye on elapsed time, GitHub limits and provider budgets. No payment or enabling of paid services is required by the project configuration.
